Agent Attention and Activity

Making it obvious when your agents need you, and what to do about it.

Proposal by Oluwaseyifunmi (Team Cybertron 2.0) · Task 1: improving human–agent interaction.

How it was made: the investigation of Ziki and this prototype were produced with Claude, an AI assistant, working from my proposal. Every name, number and time here is invented, unless a line is tagged as coming from Ziki’s source code or the live site.

In one minute
  • Problem: people who work with several agents have to keep checking Ziki to find out whether any agent is waiting for them.
  • Idea: one always-visible “Waiting on you” count, and a status for each agent that says whether it is working, waiting on you, stopped, or finished, with the action you need right there.
  • Approach: improve what Ziki already has (its Escalations page, approvals and agent status), rather than build a new system.

1. The problem

Picture someone who owns one or more agents on Ziki. An agent might ask a question, need approval before a merge, hit a problem, or finish its work. Each of those needs a different response, and each shows up in a different place: the bell, the Escalations page, the issue itself, an email.

The result is that the person checks several places, repeatedly, to learn whether anything needs them. The aim here is simple: they should be able to tell at a glance when they are needed, understand why, and respond without hunting.

2. What Ziki already does well

Everything below was checked in Ziki’s source code (Code) or on the live site while signed in (Live).

  • A dashboard “Your agents” table with the statuses Working, Waiting on you, Idle and Offline, refreshed every 30 seconds. Live
  • An Escalations page with question, work authorization, blocker, scope change, human approval and redesign types, status filters and a one-click “Approve & Unblock”. Code Live
  • Notifications and email for an agent’s question, plus a reminder after 30 minutes. Code
  • An approval banner with Approve and Reject on the issue page, and an audit log with undo. Code

3. Where people get stuck

  • The count leaves things out. The pending count and the “Waiting on you” status include only agent questions, not redesign proposals or project-rule approvals. An agent stuck on an approval can still read “Working”. Code
  • The indicator is hidden. The Escalations link and its badge sit inside the account menu, not in the top bar. Live
  • A waiting row can’t be acted on. It shows no preview of the question and no link. Code
  • Requests are buried. The bell had 23 to 25 unread items, nearly all “commented on” lines, with no filter. Live
  • Stopped and finished agents are indistinguishable. Both read “Offline” or “Idle”. Ziki records why a claim was released, but the dashboard doesn’t show it, and I found no notification that tells the owner. Code
  • The deadline is invisible. After one reminder at 30 minutes, an unanswered question leads to the agent releasing the issue after a default 4-hour wait. Code
  • Rejecting an approval tells the agent nothing. Ziki records the decision, but sends the agent no message; the agent only finds out the next time it tries to merge, when it is told “Human approval was rejected”. Approving, by contrast, resumes the merge automatically. Code
  • Only workspace owners and admins can decide an approval. The owner of the agent that is waiting may not be one. Code
  • Only questions have a time limit. Approvals and redesign proposals never expire, so a countdown only makes sense for questions. Code
  • Questions and answers are plain text. An agent’s question and your answer are both free text (up to 2,000 characters); there is no way for an agent to offer choices. Code
  • Finished work is hard to find. It is mainly visible in the audit log, which showed “No agent activity yet” for my own agent on the live site. Live

4. What I propose

  1. A “Waiting on you” count in the top bar. One number covering questions, redesign proposals and project-rule approvals, split into what is blocking an agent and what is not.
  2. Five clearly different agent states. Working, Needs input, Approval needed, Stopped and Finished, each with the relevant issue and a plain explanation.
  3. The action beside the information. A question preview with an Answer button; an approval with the rule that triggered it and Approve or Reject; a stopped agent with its recorded reason; a finished agent with what it delivered and when.
  4. A visible waiting deadline for questions, so the cost of waiting is clear. Approvals and proposals have no time limit, so they show none. In the prototype the countdown is a fixed example, not a live timer.
  5. Answers that go both ways (a proposed extension). The agent offers two or three suggested answers, each with its reason and a recommendation. You pick one or write your own, and can tick “Remember this choice”. Afterwards the agent says what it understood, and you can reply “Not what I meant”.

Two rules guide the wording: idle is never shown as finished, and stopped is never assumed to be a failure.

5. Walking through the prototype

  1. Open the prototype. The top bar says “Waiting on you · 3” with “2 blocking”.
  2. Click the pill to see the three items in two groups: two that block an agent and one that does not.
  3. Press Answer on Kite’s question. Pick a suggested answer (the recommended one comes with its reason) or write your own, optionally tick “Remember this choice”, and send. The count drops to 2, and Kite shows what it understood. Press Not what I meant to reopen it.
  4. Open Review approval for Harbor. Read why it’s needed, then choose Approve or Reject. A rejected Harbor shows “Rejected by you”, explains that Ziki sends the agent no message about a rejection, and is never shown as Finished.
  5. Review the redesign proposal. Approving or declining it does not unblock any agent, because it never blocked one.
  6. Read the Stopped (Lark) and Finished (Orca) cards, and press See what it asked on Lark.
  7. Press Reset demo to start again.

6. Answering one question: today and proposed

The side-by-side page shows all five agents both ways. In short, for a single question:

Today
  1. Notice something (bell, email or the 30-minute reminder), or remember to look.
  2. Open the account menu.
  3. Click Escalations.
  4. Find the right item in the list.
  5. Open it, then type and send the answer.

About 5 steps across a menu and two pages. An approval or a proposal follows a different path.

Proposed
  1. See “Waiting on you · 3” in the top bar.
  2. Click it, then click Answer.
  3. Type and send.

About 3 steps, from any page, and the same pattern for questions, approvals and proposals. These counts are illustrative.

7. What it builds on

Nothing here needs a new system. Each part reuses something Ziki already has:

NeedExisting Ziki piece
The list of things that need a personThe Escalations page and its pending count (countPendingEscalations), extended to include proposals and approvals
Agent status on the dashboardclassifyAgentStatus and loadOwnAgents in lib/dashboard-overview.ts, and its 30-second refresh
Approve or rejectThe issue approval banner and /api/v1/approvals/[id]/decision (only workspace owners and admins can decide)
Answering a questionThe Escalations answer form (escalation-controls.tsx), and Ziki’s delivery of an answer to the agent’s inbox
Redesign proposalsThe existing redesign proposals and their decision route
Why an agent stoppedThe recorded claim-release reasons (silence, deadline, owner unresponsive)
Contacting an agentEach agent’s existing “Messages and instructions” page

8. Boundaries

  • This is not a monitoring dashboard. It only covers what an agent needs from a person, and what happened to the agent.
  • It is not a new request system. The Escalations page and its data stay the source of truth.
  • It does not redesign Ziki. Colours, type and layout follow Ziki’s existing style.
  • It covers the hand-off moments between an agent and a person: a request, a reply, an approval, an outcome. The answer panel adds a first step towards two-way interaction (suggested answers, “remember this”, and “not what I meant”). Longer conversations and an agent learning from your decisions are not covered.
